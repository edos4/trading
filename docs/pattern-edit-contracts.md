# Pattern editor P0 contracts and evidence

Established 2026-09-14. Scope is contracts, trusted fixtures, and implementation decisions; no editor, activation, or candidate execution is enabled by P0. Typed wire shapes live in [core/pattern_edit_models.py](../core/pattern_edit_models.py). They are not runtime validators.

## Identity, artifacts and compatibility (P0.2)

`CandleIdentity` binds an index to a hashed frozen dataset and timezone-aware timestamp, symbol, market and timeframe. Daily session labels remain separate from UTC timestamps. Decode historical chart dates using the market timezone, never assume midnight UTC. Selection verifies all fields against server-owned data; exclude forecasts. Snap values must match OHLC exactly unless `snap=price`. Anchor IDs are role/occurrence IDs, not localized labels or array positions.

Canonical datasets use ordered OHLCV rows with explicit timestamps/session dates and finite numeric values; reject duplicate/out-of-order timestamps and NaN/Infinity. Canonical JSON uses UTF-8, sorted keys, compact separators, `allow_nan=False`. SHA-256 covers the exact canonical bytes. Manifest includes indicator/external-input hashes, timezone, scan semantics, and separate detection/chart cutoffs. CSV fixtures use their exact byte hashes; conversion to canonical datasets gets a new hash. Post-entry chart context is allowed in images but excluded from detector input.

IDs are opaque UUIDs, allocated by the service; version sequence numbers are transactionally monotonic per pattern. Content identity is SHA-256, distinct from object IDs. Hash candidate source, documentation, dependency manifest, base version and runtime bundle together. Reports bind candidate/dataset/dependency/validator/test hashes; Apply also verifies source mirror/base and displayed report/revision. Every required check must pass; missing previews, unresolved required expectations or unavailable tests block Apply. A new description before Apply is a new immutable revision and needs a newly bound report, even if execution results can be reused by content hash.

Sessions are mutable with optimistic generation tokens; revisions, messages referenced by revisions, artifacts and reports are immutable. Description corrections after Apply are audited events. Jobs persist revision ID, operation, idempotency key, status, progress, lease/heartbeat and cancellation; late results cannot update a newer session revision. Activation stores participating live worker IDs; stopped workers are excluded, new workers must load the registered version before accepting jobs.

Old `TradeSignal`/`BacktestTrade` constructors and annotations remain valid: P2 adds optional metadata at the end. Missing provenance means `legacy_unknown`, version null, never the newly snapshotted baseline. Retain available old resolved fields; missing facts remain unknown. Assign durable trade IDs on migration and save them before exposing editable rows. Ambiguous pattern identity requires selection. New unsupported schema/runtime versions fail closed for editing/execution while historical records remain viewable.

## Rule boundary and preservation (P0.3)

`ResolvedRules` enumerates current signal rule fields plus fill policy, class limits, sizing, costs, slippage and trusted engine identity. Dynamic state (running extrema, prior H/L, bar counters, MFE, hook state) belongs to position state, not immutable rules. Retain both signal and fill snapshots because `_open_trade` can rebase/drop stop and target levels. Snapshot the actual resulting quantity after lot rounding.

Current supported behavior:

- Entry logic can choose when to emit BUY/SELL and signal price/quantity; ordinary patterns fill signal close. Arbitrary limit/intrabar orders are not current engine behavior. Add an explicit reviewed engine policy/ABI before supporting such requests; never pretend changing `signal.price` changes the fill mode.
- Hard stop, close-trigger stop, percentage cap, target, six trailing-reference modes, activation fraction, before/after reference update, rail reclaim and bar timers are field-driven.
- `_check_exit` targets trigger on **close**, even without `exit_fill_at_close`; stops use inclusive intrabar comparisons or strict close comparisons. Default order is stop/target/reclaim/trail; `trail_first` is trail/target/stop/reclaim; timers follow price checks. Close-triggered stops may fill at the stop level. Preserve these semantics rather than inferring from UI labels.
- `time_exit_only_unfavorable` and `time_exit_min_mfe_pct` exist on signals but current `_open_trade` does not propagate them and `_check_exit` does not honor their documented semantics. Do not claim they work. P2 must explicitly implement/version these policies or reject their use in a candidate with an actionable unsupported-rule result.

Executable exit hooks **are required** for general requested exit logic beyond those fields. P2 introduces `exit_v1`: pure `evaluate_exit(candle_prefix, frozen_rules, position_state) -> {exit_price|null, reason, next_state}` with finite, bounded JSON inputs/outputs, no direct mutation/account access. When present it replaces the declarative exit evaluator, so ordering is explicit in versioned code; the trusted engine still owns fills, fees, accounting and state validation. Run imports and calls in the same sandbox as candidates, including after activation. Persist hook reference, dependency/engine hash and state on every position. On missing/corrupt runtime/hook or timeout, pause that position's automated management and surface an error; never substitute current code. Retry/recovery must not duplicate fills.

Retain trusted engine bundles by hash and compatibility ABI for old positions. Generated edits may alter selected detector/document and explicitly reviewed private helper snapshots; they cannot patch `core/backtester.py`, account code or runtime adapters. A new engine ABI is ordinary separately tested development, not an AI patch escape route. This resolves preservation without restricting the editor to drawing-only changes.

## Storage, isolation and images (P0.5)

Storage decision: workspace-root `pattern_versions/<pattern_id>/<version_id>/` immutable version artifacts; content-addressed datasets/images/drafts below `pattern_versions/artifacts/`; SQLite `data/pattern_edit/registry.sqlite3`. Resolve roots from application workspace configuration, not varying process working directories. Both interfaces share these paths. SQLite foreign keys, WAL, busy timeout, `BEGIN IMMEDIATE`, compare-and-swap base checks; fsync staged artifacts before rename, journal source-mirror writes and directory fsync, then activate registry reference. Recovery reconciles journal/hash state. Never execute through source mirrors. No cleanup of referenced versions/trades/drafts. Exclude these paths from discovery and source control in P1.

Dependencies: snapshot transitive repository helper code and frozen external inputs; preserve shared `BasePattern`/`TradeSignal` identity via a trusted ABI module. Load private helpers under a version package and explicitly rewrite/resolve absolute `patterns._helper` imports inside that package; reject unresolved/dynamic dependencies. Do not merely rename the detector while helpers still import current globals. Runtime libraries are pinned by lock/environment manifest and bundle hash. Shared helper changes create private dependency snapshots for this pattern with visible expanded diff; other patterns stay unchanged.

Sandbox choice: Linux Bubblewrap user/mount/PID/network/IPC/UTS namespaces with empty environment, private `/tmp`, read-only minimal runtime and explicit hashed inputs, no repository/home/accounts/broker files, no host sockets, no capabilities and no network. Candidate import occurs inside the boundary. Add seccomp restrictions and a delegated cgroup v2 per job with `pids.max`, `memory.max`, `memory.swap.max`; enforce CPU and file/output limits with rlimits and wall deadline with supervisor kill of the entire cgroup. Suggested defaults: 30 seconds wall, 20 CPU seconds, 1 GiB memory, 16 processes, 16 MiB output; configure only within administrator bounds. Runtime libraries need their own isolated environment; mounting the application's entire environment risks exposing configuration.

Host probe: [scripts/probe_pattern_edit_host.py](../scripts/probe_pattern_edit_host.py), run with `.venv/bin/python scripts/probe_pattern_edit_host.py`. Host-level result: bwrap, Xvfb, Ghostscript and prlimit installed; isolated home/mount/environment/network namespace probe passed; Canvas PostScript rasterized to 74×60 pixels; cgroup v2 exists but its root is not writable. Workspace-restricted attempts failed (network namespace socket denied; X display inaccessible). Probe is trusted code and is **not** a production sandbox nor a complete escape/resource test. No candidate execution is enabled.

Setup path: install distro `bubblewrap`, `xvfb`, `xauth`, `ghostscript`, Python Tk/Pillow and a pinned worker environment. Administrator provisions a dedicated unprivileged worker service with a delegated cgroup v2 subtree (`Delegate=yes` in its systemd unit) and appropriate namespace/seccomp policy. P3 must verify controllers and limits inside that subtree and run escape, fork/memory, timeout and cancellation tests before enabling execution. No delegated subtree was configured in P0. If any boundary or controller cannot be established, generation may save drafts but preview/Apply are unavailable; do not fall back to an ordinary subprocess. Non-Linux hosts use a configured equivalent Linux worker with the same isolation checks.

Tk image choice: export the actual Canvas viewport using `postscript` at explicit viewport dimensions, rasterize with Ghostscript/Pillow at calibrated scale, include selection overlays and exclude chat widgets. Basic host export passed; exact chart correspondence, fonts/DPI, zoom/pan and highlights require P6 visual testing. Browser choice: chart `takeScreenshot` plus compositing the wrapper's annotation/selection layers at the same device pixel ratio. P7 verifies overlays are included; neither capture is replaced silently by a differently framed matplotlib image. A wider deterministic chart image is additional context only.

Provider contract checked 2026-09-14: official [release](https://www.deepseek.com/en/news/deepseek-v4-1-flash/) and [vision guide](https://api-docs.deepseek.com/guides/vision/). Display DeepSeek-V4.1-Flash; configurable API model `deepseek-flash`, base `https://api.deepseek.com`, Chat Completions user content array with text and `image_url` blocks containing inline PNG data URLs. Use `detail=original`. PNG/JPEG/GIF/WebP supported; images belong in user messages. Guide limits: 48 MiB request, 32 MiB per inline image, 8192 pixels per side. P4 uses tighter application bounds and records requested/returned model IDs without secrets. Credential-dependent image interpretation smoke check is deliberately deferred to P9.4; no live provider call or credential inspection occurred in P0.
