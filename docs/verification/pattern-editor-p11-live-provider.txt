## Defect found by this test and fixed
An unpatched first run showed the candidate *backtest* failing (sandbox
unavailable) while the edit job still reported `completed`. The documented
design says a data/backtest failure after a valid version exists must fail the
job so it stays recoverable. `PatternEditService._run_or_reuse` now raises
`BacktestFailed` when the durable run is not `completed`, and the job ends
`failed`/`execution-failed`/retryable with the version preserved. Regression:
`core/test_pattern_edit_pipeline.py::test_edit_pipeline_incomplete_backtest_fails_the_job`.
